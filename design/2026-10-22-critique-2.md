## Part 2 — New-hole hunt on the REV 2 amendments

### (a) styles.ts z-index edit — **HALF MIS-FOLDED + one residual**

- **Mis-attribution [P2]:** the frozen-veil z-index is NOT in styles.ts. styles.ts
  contains only `.annota-root` (L11, `z-index: 2147483000`); the veil is inline:
  `container.style.cssText = '…z-index:2147482000…'` — **snapshot.ts:204** (contract
  comment at L109-115). COPY-MAP's "styles.ts EDIT (2 lines)" is one real line + one
  phantom line; snapshot.ts's EDIT row (portal-sweep/scroll-root/per-pin-off) does NOT
  list the veil z. As written the edit lands nowhere and drift-check fails. Fix: move
  the veil line into the snapshot.ts EDIT row.
- **Internal ladder intact:** pins 20 / cards 30 / passive 10 are all INSIDE
  `.annota-root`'s stacking context (styles.ts L28-36, L41/71/99/121/136/141/263/292);
  raising the root's own z lifts the context as a unit — zero internal reorder.
  Veil 2147483646 < root 2147483647 preserves upstream's "pins/cards paint above the
  veil" invariant (snapshot.ts L111-112).
- **Tie behavior (verified, must be pinned as an invariant):** corpus grep:
  **266 hits of `z-index:2147483647`**, 50 of `2147483646`, 10 of `2147483645` —
  including SingleFile's own `.note-selected { z-index: 2147483647 }` (card selected
  state) vs `.note { 2147483646 }`. Our injected root/style/veil are appended AFTER
  capture content on a script-free static DOM → we win every same-z tie by tree order,
  and nothing re-parents later (0 scripts in corpus). State "annota-root is the
  last root-context child; never inject before load" as the load-bearing assumption.
- **Freeze/note-resize interplay [P3 residual]:** veil at 2147483646 covers the
  ≤3646 band (plain note cards ✓) but live root-context elements at **2147483647**
  paint ABOVE the veil — e.g. a note card the reviewer SELECTED before freezing
  (`.note-selected`) bleeds over the frozen view. Pre-existing upstream property,
  worsened by this corpus. Accept + document (strip-first invariant + selected-card
  transiency); do NOT raise the veil to 3647 (it would tie-and-lose to nothing but
  must stay < root; and it would have to beat DOM order vs root — it can't, root
  mounts earlier… actually veil mounts later and would paint OVER the root — exactly
  why 3646 is the correct ceiling). Pre-import card interaction (resize handles) still
  works under our raised root: `.annota-root` is `pointer-events: none` (styles.ts L12)
  with auto only on pins/cards — clicks pass through to the cards beneath.

### (b) Deterministic import id + replay doors — **mechanism VERIFIED; static-mode divergence [P2]**

- `ThreadInput.id?: string` EXISTS (types.ts L455-464) and is the documented
  idempotency key: POST /threads checks tombstones first (`409 {deletedId:true}`,
  routes.ts:851-856), then `preexisting → 200 + replayed:true` (L858-875). **Thread
  ids are NOT re-hashed** (only a typeof-string gate, L563-565); comment ids ARE
  re-hashed server-side (`stableCommentId` author|body|createdAt, L504-515, applied
  at L585). So `singlefile-<captureId>-<noteId>-<sha1(text)[0:8]>` works exactly as
  designed in server mode. Text-hash recycling fix holds: edited note → new id → new
  thread; unchanged → 200 replay no-op; deleted → 409 skip. 409 is per-note; our own
  import loop continues for other notes as long as each POST is individually
  caught — **the design never says per-note try/catch; add one sentence.**
- **STATIC mode diverges at the tombstone door [P2]:** staticStore.create uses
  `input.id ?? newThreadId()` (staticStore.ts:390 — client id accepted ✓), replay
  returns the STORED row silently (L423-424, no `replayed` flag — harmless), but a
  tombstoned id **THROWS** (L408-422: "deletion is final; use a NEW id") — check
  order tombstone-before-replay, same as server. Transport differs: server = 409 JSON,
  static = thrown Error caught by the caller. D2c-2 describes only the 409. This is
  precisely the cross-mode divergence class round 1 warned about. Amendment: the
  import door handles BOTH shapes — 409+deletedId (server) and the thrown
  `annotakit(static): thread … was deleted` message (static) — treated identically as
  skip; pin in singlefile-import-test for both modes. (deletedIds is not exposed on
  the static store API, so message-prefix matching is the honest door.)
- Comment-id divergence across modes (server re-hashes, staticStore keeps client ids
  verbatim, L400) is benign — threads never migrate modes; GH per-comment sentinels
  are mode-locally consistent. Document, don't fix.

### (c) `Comment.source += 'singlefile'` — **VERIFIED SAFE, and the mirror behavior is the desirable one**

- Every consumer of `source` is a `'github'` comparison, none is exactly-'local':
  ghsync.ts:443/472/628, ghClient.ts:1181/1210/1244/1846, digest.ts:121/138,
  staticStore.ts:737/749, layer.tsx:2011, legacyMirror.ts:64/126. No exhaustive
  switch, no sort/badge/pull-suppress keyed on 'local'. The types.ts union extension
  compiles against all of them unchanged.
- **Mirror double-render: does NOT happen — verified both engines.** At issue
  CREATE, comments already present are stamped `ghId='issue-body'` and excluded from
  later comment pushes (ghsync.ts:441-443 create-time stamping, L471-472 push filter;
  ghClient.ts:1181 create-time stamping, L1244 push filter). The issue body itself is
  `renderThreadBlock(full)` which renders comment[0] verbatim under the literal label
  "note" (staticStore.ts:735-746). So an imported SingleFile note appears in the GH
  issue body as the original note text, exactly once, never re-pushed as a separate
  issue comment — the desirable outcome the design implies. Since imports always
  create the thread before any mirror create, the stamping always covers them.
- Pull-side: 'singlefile' comments have no ghId until stamped; pulled GH comments
  dedupe by ghId/sentinel (ghsync.ts:776-788, ghClient same) — no interaction with
  imported comments. Digest "via github" suffix only fires on source==='github' ✓.

### (e) Poll transport — **payload verified safe; layer fan-out unspecified [P2]**

- Payload: THREADS_CHANGED consumers key on storyId only — layer: `if
  (!payload?.storyId || payload.storyId === storyIdRef) refresh()` (layer.tsx:494-495);
  panel: `scope==='all' || !payload?.storyId || payload.storyId===storyId`
  (manager:357-358). `reason` is additive-safe by contract (events.ts:98-100 — "no
  consumer branches on reason, audit-verified"). Host may emit `{storyId, reason:'updated'}`.
- No selection loss: `activeThread` is independent state; refresh() only refetches
  (manager:221, 357-364; row `active = t.id===activeThread` survives, :1168). No
  storm: emit fires only on detected change; refresh triggers no mutation → no loop.
  Minor: poll-detect → emit → panel's own listener refetch = 2 fetches/change — pick
  ONE refresh owner (recommend: poll = change detector; the emit is the only refresh
  trigger).
- 5s is sane: it is a same-origin REST read of our own SQLite store; it is NOT the
  GH-API pull (ANNOTAKIT_GH_POLL 60s exists to budget GitHub rate limits — different
  resource entirely; no conflict). Static mode needs no poll (storage events,
  manager:366-380).
- **The hole [P2]:** the LAYER lives in the IFRAME — a separate document and JS heap.
  D3a says the poll "emits THREADS_CHANGED on the host channel" — that reaches the
  host panel. The layer listens on ITS channel (`sbChannel()`, layer.tsx:492-497); in
  the vendored build that is whatever `src/host/channel.ts` + inject.ts wire. Nothing
  in REV 2 says the poll emit reaches the iframe. Fold of 1b-P2-4 is panel-only;
  without fan-out the layer's pins/cards go stale on agent replies in server mode.
  Amendment: ONE channel instance in the HOST window, handed into the iframe before
  script injection (same-origin `contentWindow` assignment); layer's `sbChannel()`
  resolves it (window.parent reach); the poll emits once — panel AND layer refresh.
  Cross-realm EventEmitter references are fine same-origin. Also note the standalone
  server's own broadcast (serverChannelHook) feeding the same channel means local
  mutations arrive twice (broadcast + poll) — harmless dedupe-by-refresh-seq
  (layer.tsx:458-464), document it.

### (g) anchor.ts `/^single-file-/` exclusion — **VERIFIED sound**

Filter is `className: (name) => name.length > 3 && !name.startsWith('_') &&
!/(?:^|[-_])(?:css|scss|module)/.test(name)` (anchor.ts:115-116). Adding
`/^single-file-/.test(name)` exclusion is start-anchored: it can only drop classes
literally beginning `single-file-` — in this ecosystem exclusively SingleFile's own
injections (`single-file-note`, `single-file-highlight-*`). Worst-case false positive
(a page's own `single-file-…` class) = that class omitted from the selector = honest
ladder degrade, and conversely selectors become MORE robust (survive
highlight-removal/re-save). One line, tested, correctly COPY-MAP'd.

### (h) Dangling/page-level imports as panel-only threads — **MIS-FOLDED (the round-2 P1)**

D2c-3/4 say "The HOST filters them from the thread list it hands the layer (zero
vendored edits)". **The layer is handed nothing — it PULLS.** Dev mode:
`dataRef.current.list(storyIdRef.current)` → REST `getThreads` (layer.tsx:448-460);
static mode: `store.list(s)` (layer.tsx:559-565). The five COPY-MAP layer.tsx
substitution points do not include dataRef, and no host→layer thread-list seam
exists upstream. A dangling import stored as `kind:'pin'` with a fragment (note
offsets) + the REQUIRED bbox (validateTargetShape routes.ts:534-543 demands
`{x,y,w,h}` numbers and `context.tag`) will fail css/text/fingerprint resolve and
fall to the ORPHAN RUNG — which RENDERS a pin at the stored fragment ("pin renders
at stored fragment bbox"). I.e. the exact fabricated-evidence pin round-1 P1-3
banned, re-entering through the data flow the fold misunderstood. Also panel→layer
FOCUS_THREAD on such a row (manager:418-420) would flash the phantom.
**Amendment (minimal, honest):** layer.tsx EDIT gains a sixth surgical edit — filter
in `refresh()` (or a dataRef.list wrapper): drop threads carrying the dangling
marker, e.g. additive `TargetContext.singleFileDangling?: true` (one more line in the
types.ts EDIT) — used by BOTH the layer filter and the panel badge key. "Zero
vendored edits" must be struck. Pin with a static+server fixture test.
Verified along the way: the PANEL is safe — rows never branch on target/anchor
(manager:1167-1276 renders status/#, gh chip, dates, comments only) so pinless
threads render fine; `uiOrphan` comes from the layer's UI_STATE (manager:829) and
stays honest after the filter; count divergence (panel threads.length includes
dangling, layer total excludes) is cosmetic — document. The badge needs its
discriminator field (above) — `singleFileNoteRef` alone cannot distinguish dangling
from resolved imports.

### (i) Freeze gate vs hotkeys — **host-button gate is insufficient [P2]**

Freeze has THREE doors: host toolbar button (ours), UI_COMMAND 'freeze' over the
channel (layer.tsx:1073), and the DEFAULT_HOTKEYS `freeze: 'alt+i'` (hotkeys.ts:38,
handler layer.tsx:805-841). All layer doors are refused ONLY by the layer prop:
`frozenView === false` (layer.tsx:810-811 refuses with a hint; UI_STATE
`frozenViewEnabled:false` hides the manager button, layer.tsx:709-712). Disabling
just the host button leaves ⌥I + UI_COMMAND live → full-DOM clone on a 66MB capture.
**Amendment (zero new mechanisms):** inject.ts mounts the layer with
`frozenView={false}` for captures over the manifest size threshold — upstream
already implements the complete gate; the host just has to use it per-capture.

layer.tsx/snapshot.ts/inject.ts + 4 design-text edits) and the design is final —
no third adversarial pass should be needed beyond confirming the REV 3 diff.
